# Teach and Repeat

## Establish the working agreement

Read the latest request and current authoritative sources. Carry forward an explicit preference to document ongoing work when it is present. Keep execution within the task's existing authority. Treat a teaching request as permission to document the requested work, not permission to expose secrets, publish, spend, widen account access, or change unrelated settings.

Use the relevant specialist skill to perform the task. Reuse Research to Implementation for executing research recommendations and Skill Creator for any personal-skill operation. Avoid duplicating their detailed procedures.

Scale the lesson: explain a simple completed action briefly; produce a saved guide for a substantive workflow. For recurring work, update the existing guide and skill when suitable. Create a distinct skill only when it adds a repeatable procedure; avoid one duplicate skill for every task.

## Capture authentic evidence

Determine the recording capability before promising a recording. Begin supported capture before the actions it purports to record. Record observable inputs, steps, outputs, real failures and fixes, and checks. Keep private reasoning out of the guide.

Exclude authentication entry, credentials, verification codes, private sources, unrelated account details, and infrastructure secrets from recordings and logs. Pause capture before sign-in. For account setup or credential offers, read [secure-account-setup.md](references/secure-account-setup.md).

If continuous recording is unavailable, explain the limit and offer a supported terminal replay, captured-step walkthrough, or written guide. Label which it is, its start point, any changed timing or abbreviated paths, and omitted steps. Do not label reconstructed slides or screenshots as a live screen recording. Preserve the original permitted capture alongside a rendered replay when useful.

Keep a compact action record with action, status, observed evidence, verification, and next dependency. Distinguish applied, prepared, blocked, failed, deferred, and rejected. Do not infer success from a submitted request or command that only prepared a result.

## Write the teaching guide

Build it from observed actions and current sources. Include:

- The intended result and prerequisites, without requiring secrets in chat.
- The steps taken and why each matters.
- The visible completion signal and actual check for each important step.
- A real failure and recovery when one occurred.
- Recording scope and omissions; separate demonstration from pending instructions.
- The smallest remaining user step and how to verify completion.
- A short repeat recipe, with variable inputs and boundaries.

Use the user's platform for handoff directions. Verify uncertain product paths from official documentation or visible controls. Preserve existing instructions and user content when applying configuration; inspect before merging and confirm saved state afterward.

Maintain the reusable skill with Skill Creator when authorized. Validate structure, use a realistic bounded forward task when appropriate, save it, and verify installed state. Keep the user-facing guide separate from the skill's operational content.

## Verify and preserve

Check the actual deliverable and its usability. Inspect visual artifacts and playback or decoding of recordings as appropriate. Confirm account changes from saved visible state, installed skills from the supported installation result, and schedules from returned task state. Mark missing checks explicitly; do not turn these checks into claims of measured performance gains.

Save requested guides and recordings through the environment's artifact rules, retaining existing file identity for updates. Do not claim that a preference is globally applied or remembered everywhere until an available setting confirms it. Preserve standing preferences in authorized current project guidance and the relevant skill.

Return the usable result first, guide and recording links, any installed skill name, concise actual verification, and the specific blocker. Keep login handoffs free of teaching narration and resume documentation only after authentication completes.
